Every external call in Grasp OS — whether from a workflow step, an App's server method, or the agent — goes through one place: `apps/connect`, the Connector Worker. This is the only part of the system where OAuth tokens exist in plaintext. App code, workflow code, and agents never hold tokens; they call through **connection stubs** that connect resolves to real credentials at egress. This design means a bug or a compromised App cannot exfiltrate tokens, and every outbound call is audited.

## Connections

A **connection** is an OAuth-linked account: a user (or an admin, for shared accounts) has signed in to a third-party service and authorised Grasp OS to call it on their behalf. Connections have IDs; Apps reference them through permission bindings (e.g., `OUTLOOK`, `GDRIVE`).

Connections come in two kinds:

<CardGroup cols={2}>
  <Card title="Personal" icon="user">
    Owned by one member of the organisation. Only Apps whose owner is that person can use the connection in a triggered run. The connection's tools can only be called on behalf of its owner.
  </Card>
  <Card title="Shared" icon="users">
    Connected by an admin on behalf of the organisation. Any App an admin grants access to may use it.
  </Card>
</CardGroup>

## The MCP protocol

Native connectors in Grasp OS implement the [Model Context Protocol](https://modelcontextprotocol.io) (MCP), a JSON-RPC protocol over HTTP. Connect acts as the MCP client; each connector is a stateless MCP server running in its own isolate.

The protocol has two relevant methods:

```text
tools/list  → returns the available tools and their input/output schemas
tools/call  → calls a named tool with arguments, returns structured content
```

Each connector registers tools by name. Connect looks up the tool's manifest to decide, before running any code, whether the call is read-only or has side effects, which resource it targets, and which routes it may send requests to. Only then does it invoke the tool's `run` function.

```typescript
// packages/connector-kit/src/connector.ts
export interface ToolDefinition<Input extends z.ZodObject, Output extends z.ZodObject> {
  /** The action's name, as permissions name it, such as `mail.list`. */
  name: string;
  description: string;
  input: Input;
  output: Output;
  /** Only a read-only tool runs without an idempotency key. */
  readOnly: boolean;
  destructive?: boolean;
  /** The one input property that selects the resource it acts on. */
  resource?: Extract<keyof z.input<Input>, string>;
  /** The only requests this tool may send. */
  routes: readonly Route[];
  run: (input: z.output<Input>) => Promise<ToolResult<z.input<Output>>>;
}
```

Tool input schemas must be strict objects — `z.strictObject` — all the way down. Unknown keys are refused, not dropped. This ensures connect can fully inspect and validate every call before it leaves the platform.

## How connect adds the token and enforces egress

When a tool's `run` function calls `fetch`, the request doesn't go directly to the internet. It goes to connect's **egress handler**, which:

1. Checks the requested host against the connector's declared `hosts` list — requests to undeclared hosts are refused.
2. Verifies the request matches one of the tool's declared `routes` — a route not listed in `routes` is refused.
3. Adds the connection's OAuth token (Bearer or other scheme, depending on the provider) to the outgoing request.
4. Enforces idempotency: a non-read-only call without a valid idempotency key is refused with `connect.idempotency_key_required`.
5. Forwards the request and returns the response to the tool's `run` function.

The token is **never in the isolate**. The connector code can only reach the provider through routes it declared, with a token it never sees. This satisfies threat model R9 in `AGENTS.md`.

## Capabilities: signed tokens for per-call access

Core issues a **capability** — a short-lived signed token — for each call to connect. The capability encodes which connection, which actions, and optionally which resource (e.g., a specific mailbox or drive) the call may use. Connect verifies the capability's signature before making any external request.

Capabilities are generated by the `CAPABILITY_SIGNING_KEY` and are valid only for the duration of the call. They cannot be reused or transferred. This means a compromised App session cannot access connections beyond what its capability permits for that single call.

## Connector events

Native connectors can report **events** — notifications from the provider that something changed. Workflow event triggers (`type: "event"`) subscribe to these. Connect polls or receives webhooks from the provider and delivers matching events to the workflows that declared triggers for them.

The two native connectors report the following events:

<Tabs>
  <Tab title="Microsoft 365">
    Events are delivered within about a minute.

    | Event type | Read action | Payload fields |
    |------------|-------------|----------------|
    | `m365.mail.received` | `mail.list` | `mailbox`, `id`, `folder` (`"inbox"`), `subject`, `from` (`{ name, address }`), `receivedAt`, `hasAttachments`, `conversationId`, `internetMessageId`, `webLink` |
    | `m365.file.created` | `files.list` | `drive`, `id`, `name`, `mimeType`, `size`, `folderId`, `createdAt`, `webUrl` |

    The `m365.mail.received` event fires for mail arriving in a mailbox's inbox. The `m365.file.created` event fires for a file created in a drive, in any folder.
  </Tab>
  <Tab title="Google Workspace">
    Events are delivered within about a minute.

    | Event type | Read action | Payload fields |
    |------------|-------------|----------------|
    | `google.mail.received` | `mail.list` | `mailbox`, `id`, `threadId`, `folder` (`"inbox"`), `subject`, `from` (`{ name, address }`), `receivedAt` |
    | `google.file.created` | `files.list` | `drive`, `id`, `name`, `mimeType`, `size`, `folderId`, `createdAt`, `webUrl` |

    Unlike `m365.mail.received`, a message moved into the inbox later is **not** reported — only mail as it first arrives. Google file events only fire for shared drives; a person's My Drive is not monitored through a permission on the whole connection.
  </Tab>
</Tabs>

An event is only delivered to a workflow if the App holds a permission on the connection (or the specific resource the event relates to) that allows the read action the event names. For a personal connection, only the App whose owner is the connection's owner receives events.

<Warning>
  Event payloads and email sender fields are untrusted data — they are whatever the external provider or sender wrote. A mail's `from` field is not vouched for by Grasp OS. Treat every incoming payload as untrusted input and validate it before acting on it.
</Warning>

## The two native connectors

Grasp OS ships two native connectors built with `@grasp-os/connector-kit`:

<CardGroup cols={2}>
  <Card title="Microsoft 365" icon="microsoft">
    Uses Microsoft Graph (`graph.microsoft.com`). Covers mail (read, send, move, label), calendar (events, availability), and files (OneDrive, SharePoint drives — read, download, upload). OAuth scopes include `Mail.ReadWrite`, `Mail.Send`, `Calendars.Read`, `Files.Read.All`, and `Sites.Read.All`.
  </Card>
  <Card title="Google Workspace" icon="google">
    Uses Gmail and Google APIs (`gmail.googleapis.com`, `www.googleapis.com`). Covers Gmail (read, label, draft, send), Calendar (read events), and Drive (read files in shared drives). OAuth scopes: `gmail.modify`, `calendar.events.readonly`, `drive.readonly`.
  </Card>
</CardGroup>

Each connector is versioned (`0.2.0` for both currently) and loaded by connect at startup. Both follow the same `defineConnector` contract:

```typescript
// packages/connectors/microsoft-365/src/index.ts
export default defineConnector({
  name: "microsoft-365",
  version: "0.2.0",
  provider: "microsoft",
  scopes: [
    "User.Read",
    "Mail.ReadWrite",
    "Mail.ReadWrite.Shared",
    "Mail.Send",
    "Mail.Send.Shared",
    "Calendars.Read",
    "Calendars.Read.Shared",
    "Files.Read.All",
    "Sites.Read.All",
  ],
  hosts: [graphHost],
  tools: [...mailTools, ...calendarTools, ...fileTools],
});
```

```typescript
// packages/connectors/google-workspace/src/index.ts
export default defineConnector({
  name: "google-workspace",
  version: "0.2.0",
  provider: "google",
  scopes: [
    "https://www.googleapis.com/auth/gmail.modify",
    "https://www.googleapis.com/auth/calendar.events.readonly",
    "https://www.googleapis.com/auth/drive.readonly",
  ],
  hosts: [gmailHost, apisHost],
  tools: [...gmailTools, ...calendarTools, ...driveTools],
});
```
